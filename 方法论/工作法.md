## 0. 目标探索（前置阶段：先把"目标"探索清楚）

> 动机：很多任务进来时用户给的只是**模糊意图**，不是清晰目标（如"优化 dsh 框架"）。规格文档的三要素
> （目标/范围/约束）实际上由 AI 生成——这个"目标生成"过程本质是一次**未显式化的探索**：AI 在后台预演了一遍
> （现状调研/方向筛选/边界定夺）才觉得"目标可判"。这轮隐式探索不受约束，目标质量无把关、易带偏见
> （顺着用户意图写、不质疑方向是否最优）。v2 把它显式化为第 0 阶段。

- **触发（目标模糊度评估）**：满足任一 → 走目标探索：
  ① 用户只给了意图、没给可验收目标（"优化/改进/做个 X"，没说做到什么程度）；
  ② 存在多个竞争方向需先探测后定；
  ③ 验收标准无法前置锁定（不知道答案长什么样）；
  ④ AI 对任务领域知识不足（认知缺口，见下方学习环挂钩）。
  目标已明确（用户直接给出可验收目标）→ 跳过第 0 阶段，直接判型进入执行。
- **目标探索契约**（复用《探索契约模板》，模板见 `templates/探索契约模板.md`）：
  方向清单 + 已知/未知/假设清单 + 终止条件（轮数/时间/边际收益阈值）+ 报告格式（候选目标清单）。
- **执行（委派探索资产全部启用）**：
  - **L0 补盲**：主代理先出第一版目标理解 L0；子代理对 L0 对抗式补盲，产出补盲清单——专门质疑"AI 顺着意图写目标"的偏见（实测：壳插件边界问题补回 5 项 L0 结构性盲区）。
  - **整合器角色**：子代理 = 主控 + 整合器，负责补盲/选点/分发/整合；**主代理不读孙代理原始报告**，要细节让整合器回溯（裁决 C2）。
  - **取证协议（防脑补）**：孙代理必须带实测/检索协议（空结果 = 合法终态），否则退化为脑补。
  - **三类字段**：收敛产物必须保留：证据来源 / 没找到什么 / 对目标的质疑（裁决 C3）。
  - **扇出 4~6 为甜区**：并行分发 4~6 个点为甜区，>10 碎片化 + 合成灾难（裁决 C4）。
  - **输出限长**：孙代理输出限长结构化（≤600 字/点），控制合成上下文膨胀（实测教训：主代理亲自合成导致上下文 +13%）。
  - **调度**：目标探索默认**单轮分发 + 收敛**（快）；单轮收敛不充分（候选目标互斥/分歧大）再进**波次迭代**深挖（裁决 C1：单轮作首波，波次为深挖备选）。
- **收敛判据**：收敛出 2~3 个候选目标 + 收敛理由 + 已知/未知/假设 → 交用户拍板（或自主模式按三环收敛）。
  目标探索的"验收" = **收敛质量**（无偏见、覆盖可行空间、可落成可验收规格），不是"找到唯一正确答案"；
  无终止条件会退化成"目标永远不确定"，必须复用契约的终止条件字段。
- **学习环挂钩（能力不足向外学习）**：若候选方向因知识不足收敛不了（锚点检测信号）→ 触发学习环（§7.3）：
  先产搜索契约 → 请求开梯子 → 找可 dry-run 的"物" → 学会后再收敛目标。
  **学习环反哺目标探索质量**——"目标清晰是**学习补齐后**探索的结果"，不是一次性猜出来的。
  目标探索 = 对「任务目标空间」的探索式学习；学习环 = 对「AI 自身能力缺口」的探索式学习，同一底层能力两个层面。

## 1. 判型（目标探索收敛后的二次判型）

- 判定前置：第 0 阶段收敛产物（候选目标清单 + 已知/未知/假设）就绪后，才做本判型。
- **工程模式**：目标可判、验收可预置、交付物明确（重构 / 实现 / 部署 / 修复）
  → 用《规格文档模板》（目标 + 验收），**三要素直接取自目标探索产物**，不重写。
- **探索模式**（满足任一）：① 验收标准无法前置锁定（不知道答案长什么样）；② 目标开放（调研 / 评估 / 找方案 / 可行性 / 技术选型）；③ 搜索空间大且方向未知；④ 存在多个竞争方向需先探测后定
  → 用《探索契约模板》（方向 + 终止条件），**不要**用规格文档——验收条款强制提前锁定 = 带证实偏见搜索
- 判型错误没有自动纠偏机制，判错了由事后证据暴露，下个任务修正。

> **目标探索 vs 探索执行的区别**：§0 目标探索探索的是"目标本身"（这个任务该做成什么）；§6 探索执行是目标已定
> （收敛并拍板后），探索"怎么做/答案是什么"。两者都叫探索、共用委派探索资产，但对象不同、阶段不同。

## 2. 三层子代理执行模型（编排硬约束）

```
主代理（写提示词、验收） 
  → 主控子代理（项目经理：建目标 + 任务列表 + 分工表，调度任务）
      → 孙代理（执行层：实际干活，产出物证）
```

- **第一步必须派一个主控子代理**，由它建目标、任务列表、分工表后再派孙代理执行；
  禁止主代理直接派执行子代理（扁平编排）。
- 判定是否合规：派发前有无 目标 + 任务列表 + 分工表 产物、有无主控子代理标识、最终有无集成验收产物。
- 子代理 ≠ 只有一层：执行可以继续拆（三层模型指角色分层，不是层数上限）。
- 工具代称（括号内为 dsh 中的实现参考）：目标管理（goal）、任务看板（task-board）、派生子代理（subagent）。
- **触发线（裁决 C5）**：什么时候值得走三层——
  ① 按 §0 目标模糊度评估进入的正式任务默认走三层；② 小任务（一问一答不用工具 / 1-2 步单点操作 /
  纯聊天 / 强顺序依赖且必须主代理串）可不拆、不走三层；③ 拿不准时拆（犹豫就拆，不犹豫才不拆）。

### 2.2 目录级输入隔离（v2.1 吸收豆包稿 第 6 步 / R2 / R7）

- 执行侧（主控子代理 + 孙代理）**只给冻结条款路径**，禁止给过程目录（草案 / 攻击报告 / 采纳说明 / 审计报告）。
- 攻击（或审计）代理与执行代理必须是两个独立实例、不共享上下文；攻击代理一次性使用，攻完即终止。
- 判定合规：执行侧产物中若出现过程材料的内容（草案措辞、攻击意见、采纳理由）= 隔离违规。

### 2.3 上报格式四项（v2.1 吸收豆包稿 §9）

- 链路：孙代理 → 主控子代理 → 主代理 → 用户，**逐级上报，不得越级**。
- 上报必带四项：① 问题描述；② 涉及条款条目编号；③ 影响范围；④ 建议处置（供上级决策，**不替上级拍板**）。
- **调条申请**：孙代理需查看所持片段外的条款条目时，不得自行翻找，先向直接上级提调条申请，由上级供条或继续上报。

### 2.4 高风险判定口径（v2.2 · D1，澄清 v3.1⑤ 之②）

- v3.1⑤ 高风险三类硬条件之二「**改动≥3 文件或跨模块**」中的「改动」，以三项**实质判据**为准：
  ① **覆盖 / 修改既有文件**；② **对外发布**；③ **跨模块代码改动**。
- **纯新建交付物**（在新建目录下创建新文件，不覆盖任何既有文件）**不计入**「改动」。
- **理由**：该条立法意图是**爆炸半径**（不可逆性与影响面），文件数量本身不是风险源；按字面执行会把测试类任务的正常交付误判为高风险，白付一次独立审计。
- **验收**：凡声明「命中高风险②」的任务卡或交付报告，必须同时给出①②③三项实质判据的结论；**仅凭文件数量声明命中 = 不合格**，主代理格式门禁即退回。

## 3. 子代理任务提示词硬三条

派发每个子代理时，任务提示词必须包含以下三条（缺一不可）：

1. **空结果 = 合法终态**：检索/搜索无结果时禁止自动重试、禁止扩大范围重搜、禁止假装在跑；确需重试最多 2 次到顶即停。
2. **只做分派的那一件事**：产出明确的结果/证据/交付物，不得自由扩展任务边界。
3. **卡住立即上报**：报告「卡点 + 已尝试动作」，禁止静默空转。

主代理验收时逐条核对：是否空转、是否超范围、是否把空结果当成功；汇总附「完成了什么 / 证据在哪 / 没找到什么」。

**补充（裁决 C2）**：涉及整合/合成的环节，主代理不重读孙代理原始报告，要细节让整合器（主控子代理）回溯。

### 3.1 可原样转发的自足段落（v2.1 吸收豆包稿 §7.1-7.4）

> 用途：跨层转述是口径漂移的主因。以下三段为**成品段落**，发包时整段逐字附带，禁止改写、禁止精简。
> **自足性判据**：每个术语在段落内首次出现即自带定义；禁止「如上所述」「按前述章节」等离开上下文即失效的外部指代；
> 发包前逐段自检，不合格重发（缺段的任务卡不合格、不得发出）。

**甲・攻击 / 审计代理发包段**（一次性独立实例，攻完即终止）

你是一次性独立红队攻击（或独立审计）代理，只攻不建：只查找问题、不修改条款、不产出任何业务产物；攻完即终止，且你与任何执行代理不共享上下文。【攻击对象与读取要求】攻击对象统一表述为「条款或探索方针」；输入仅为
指定文件的绝对路径，你只读取该路径文件；若文件不可读或不存在，立即停止、原样回报确切报错，禁止虚构或脑补任何内容。
【攻击维度清单（逐项排查）】流程断点 / 验收可检验性 / 范围漏洞 / 约束冲突 / 机制可行性 / 隐藏假设 / 定义模糊 / 口径遗漏，共八个维度。
【严重级标准】高＝放行后跑不通或产物必然出错；中＝扯皮空间或显著质量影响；低＝表述结构优化。【报告条目 schema】每条按
「编号 | 位置 | 严重级 | 问题描述 | 后果 | 修改建议」六列书写，末尾给出总体结论与「必修最小集合」。【纪律】不改条款、不建产物、
不可读即停并如实回报、报告落盘并回报后实例立即终止。【术语自带定义】普通问题＝同时满足「不影响最终结论成立、
不违反条款、直接上级处置即可消除」三条件者；鲁棒性错误＝事实性错误、数据错误、违反条款、技术路线性错误（机制上跑不通或
导致返工级偏差）、会导致最终结论不成立的错误。

**乙・主控子代理行为段**（向执行 / 探索主控子代理下发时整段发出）

你是执行（或探索）主控子代理。你只接收已放行的冻结条款，禁止列举 / 读取过程目录，禁止获取攻击报告、草案、采纳说明与审计报告。
你按任务卡骨架发卡，且每张任务卡必须逐字附带丙・孙代理行为段，缺段的卡不合格、不得发出；拆分维度与卡数你自定，但字段不许裁剪。
你的处置权限严格按 §2.1 四级权限处置表中「主控子代理」一行：可做普通问题打回重做并计次、不改条款前提下调整拆分 / 增删更换孙代理 /
重发任务卡、应孙代理申请提供条款片段、逐卡逐字段内容验收；禁止修改条款或对条款实质作解释（只能原样转述，疑问上报）、禁止读取过程目录、
禁止跳过内容验收、禁止发出缺丙段的任务卡。你负内容验收与记录责任与逐级上报责任（按 §2.1 权限表与 §2.3 上报格式四项）。
【术语自带定义】普通问题＝同时满足「不影响最终结论成立、不违反条款、直接上级处置即可消除」三条件者；鲁棒性错误＝事实性错误、
数据错误、违反条款、技术路线性错误、会导致最终结论不成立的错误；内容验收＝逐卡、逐字段对照本卡验收标准核对并记录。

**丙・孙代理行为段**（每张任务卡必须逐字附带）

你的自修边界仅限：①本任务卡内、不违反条款的自我修正；②在卡指定工具 / 方法范围内选择具体实现手段，此外不得自决。以下五类情形必须上报：
①鲁棒性错误（事实性错误 / 数据错误 / 违反条款 / 技术路线性错误 / 会导致最终结论不成立的错误）；②条款矛盾或缺口；③需越出本卡范围；
④卡内信息不足；⑤认为任务卡不可行。上报必带四项：问题描述、涉及条款条目编号、影响范围、建议处置（供上级决策，不替上级拍板），

## 4. 证据验收（客观化门禁）

> 目的：防止"运动员兼裁判"——干活的人又自己判"完成了"。
> 办法：把"什么算完成"变成**可见、冻结、可复现**的检查条款和脚本，由机器执行、由用户抽查。

流程（每个操作类任务走这条流水线）：

```
1. 接任务
2. 起草《验收条款》中文清单 + 检查脚本（草案）
   —— 条款必须：量化、可对照、有客观判定方法；禁止"应该没问题"这类措辞
3. 用户审查（抽查即可）：重点看条款是否太松、是否量化、判定方法是否客观；
   用户说"冻结"（或"开始吧"）= 默认冻结；说"免审"= 按模板默认从严执行
4. 冻结后不得再修改条款和脚本（除非用户要求）
5. 实现
6. 跑验收脚本 → 输出 [PASS]/[FAIL] 报告，全部 [PASS] 才算完成
7. 附自证清单（做了什么、证据在哪个文件/哪行/哪个输出），用户抽查关键项
8. 用户拍板"完成"或要求返工
```

**条款书写铁律**：① 量化（能用数字不用形容词）；② 客观判定（每条都有机器可检查的方法：文件内容 / 端口状态 / 命令输出 / 截图）；③ 证据优先（真实产物 > 口头说明）；④ 短小（每条一行能看懂，用户不细审也能抽查）。

**完成定义** = 验收脚本全绿 + 自证清单 + 用户抽查通过。三者缺一不算完成。

### 4.1 断线/恢复防坑（实测教训）

- 会话重启/断线后，模型可能把历史里一句自我总结（"已全部完成/结论已给出"）当成已完成事实继续，而不去验证——问它"做完了吗"只会顺着说做完了。
- 对策①：**关键验收必须落成文件物证**（报告写入文件，不只在对话里）——对话会丢、总结会糊弄，文件不会。
- 对策②：恢复后第一句固定问「你上次真的执行并验收了吗？给实际产物路径和验收数据，别用总结糊弄」。
- 对策③：主代理被"等子代理通知"卡住不算完成——等待期间必须产出独立成果或显式自查；把"等通知"当终点是编排层空转。

### 4.2 语义 ground truth 验收（实测教训）

- 自写单测通过 ≠ 行为语义正确（实测：覆盖率 98% 仍出现"假修复"，错误语义被测试断言固化）。
- 涉及数值/统计/单位换算/转换类逻辑的任务，验收标准必须包含**独立于被测实现的语义基准**（测试方或第三方预置的手工算例/期望值），以 ground truth 对照判定，禁止仅凭自写单测通过判定行为正确。

### 4.3 验收判定口径与脚本同源（v2.2 · D2）

- 一切验收 / 评分脚本的**判定口径**（计字方法、章节归属、列数、覆盖率算法等）必须在**条款冻结时一并冻结**，与条款正文同源。
- 此后任何口径变更（含事后补充的放行口径）**必须同步更新对应脚本并重跑**，不得只改口径不改脚本；重跑输出须写**新物证文件**，不得覆盖旧物证。
- **验收（可机检）**：① 脚本内每条断言可追溯到条款条目编号；② 口径变更后有新的重跑输出物证（新文件 + 与旧物证并存）。
- **工具面统一口径（附注）**：物证行数核对一律用 `(Get-Content -Encoding UTF8).Count`；**禁止混用 `Measure-Object -Line`**（同一文件实测真值 69 行、`-Line` 得 43 行，会污染物证清点）。

### 4.4 条款可判定性自检（v2.2 · D3）

凡写入规格文档 / 任务卡的**可机检条款**，交付前须过四项自检：

1. **量化口径自足**：字数 / 计数 / 行数类必须写明计什么、不计什么（如「仅计 CJK，去标题/表格/引用行」）；
2. **引用件随附**：条款引用的模板 / 附录必须随附本体，或明文声明「某三列即全部要求」；
3. **章节归属明确**：附录 / 术语表是否计入章数须写明；
4. **量词已定义**：「至少 / 恰 / 一句 / 若干处」等不得作为判定标准，须替换为可数口径。

**未过自检的条款不得发出**（效力等同 §3.1「缺段的任务卡不得发出」）。
**验收（可机检）**：规格文档末尾附「可判定性自检」勾选块，四项逐条打勾；执行中发现未覆盖的歧义，按 §2.3 四项格式上报。

## 5. 提问治理（用户交互预算）

- **分级**：
  - A 阻塞必问：用「开工必要条件清单」客观化，缺即问不靠感觉（如：缺楼书、缺权限、缺素材）
  - B 可授权：如网络代理、安装工具——能声明默认就给默认
  - C 默认 + 声明：「默认 X，有异议说一声」
- **批处理**：问题打包问，不零散打断。
- **预算**：打断 ≤ 3 次、每次 ≤ 8 问；超限后末班车（≤ 10 问）强制转自主模式。
- **自证优先**：能查的查、能测的测、能标注的标，不拿问句当偷懒出口。
- **需要用户拍板的问题必须走显式提问机制**（选项化提问），禁止在正文里夹带问句等用户打字；用户未答复前，关键动作（落盘/开工/删文件）一律冻结。

## 6. 探索模式（执行阶段的探索变体，吸收委派探索资产）

> 边界：探索模式是**流程参数变体，不豁免三层模型**（仍须主控 + 孙代理，编排硬约束与降级预案照旧）。

- **探索契约**（替代规格文档，模板见 `templates/探索契约模板.md`）：
  方向清单 + 已知/未知/假设清单 + 终止条件（轮数/时间/边际收益阈值——这是探索唯一的"验收"）+ 报告格式（发现/未发现/负发现/建议下一方向）。
- **孙代理探索版约束**（替代三硬条）：
  ① 空结果 = 合法终态，但必须报「试了什么 / 为何可能为空 / 建议的下一方向」——空结果常是重要负发现，不是失败；
  ② 允许自由扩展，但扩展必须申报（方向 + 理由），足迹可溯；
  ③ 卡住报「进展快照」（已尝试动作 + 中间结论），禁静默空转。
- **委派探索资产并入**：
  - **取证协议**：孙代理必须带实测/检索协议（空结果 = 合法终态），否则退化为脑补（信息分散、需取证场景强制）；
  - **三类字段并入探索日志**（裁决 C3）：每份探索日志保留 证据来源 / 没找到什么 / 对目标的质疑；
  - **扇出 4~6 为甜区**（裁决 C4）：并行探测 4~6 点为甜区，>10 碎片化 + 合成灾难；
  - **输出限长**：孙代理输出限长结构化（≤600 字/点）。
- **波次调度**（主控层）：并行探测 → 汇总足迹 → 定向深挖 → 收敛判定（用终止条件）→ 报告；依据足迹决定下一波方向，不是一次分完工。
- **足迹代替物证**：探索子代理产出「探索日志」（尝试→结果→教训→负发现），负发现单列——探索的价值一半在排除。
- **模型分档建议**：探索/推理阶段用强推理模型，执行/整理阶段降档便宜模型——预算花在「发现」上，不花在「抄写」上。

## 7. 两档模式 + 三环设计（用户在场 / 用户离场）

### 7.1 两档模式 + 逃生门

- **交互模式（默认）**，两把钥匙：
  - ① 不确定 → 问（拿不准复述确认；换几条路走不通就停下来问）
  - ② 无来源的事实禁止进产物，一律标注缺失（硬规则，不依赖自信度，防编造）
- **自主模式**：用户开场声明「别来问我，一个人干完」才启用；此时学习/修订/后验三环替代用户。
- **逃生门**：不确定就问（低阈值），自主模式也不豁免。

### 7.2 提问治理（两档共用）

A 阻塞必问 / B 可授权 / C 默认+声明；批处理打包问；预算 打断 ≤ 3 次·每次 ≤ 8 问，超限末班车（≤ 10 问）后强制转自主；自证优先；干预率超标即调阈值（实测校准参数）。

### 7.3 学习环（自主模式主力：能力补齐）——**横切机制**

> 学习环不隶属某个阶段，而是贯穿 §0 目标探索、§6 探索执行、工程执行的横向能力保障。
> **与目标探索的挂钩**：§0 收敛不了 → 触发学习环 → 补齐认知后再收敛（"向外学习"直接反哺目标质量）。

- 能力缺口三信号：锚点检测 / 失败返工 ≥ 2 次 / 沉淀覆盖。
- 学习检查点：触发学习 → 先产搜索契约 → 请求开梯子 → 找可 dry-run 的"物"（能跑的最小实例）。
- 技能卡 M1-M4：多源交叉 / 可证伪 / 试点先行 / 可归因修正。
- 学习成果沉淀为可复用技能条目，同型任务免重学（含目标探索的已知/未知清单也可沉淀）。

### 7.4 修订环（自主模式主力：产物修订）

- 复述确认必含关键属性维度：来源 / 形态 / 数量 / 风格。
- 源文件双轨：结构化源 + 渲染物，修订改源重渲染。
- 修订协议：页/块标识、分歧点清单、影响面清单、未涉及产物语义级未变、回归只重跑受影响子链。
- 渲染类产物修订后强制导出每页截图 + 人工/盲审抽查。
- 用户指定外部素材时自绘/本地替代 = 擅自降级，必须申报。

### 7.5 后验环（自主模式主力：结论可信度）

- 数据卡：数值 / 来源URL / 采集日期 / 口径 / 可信度 / 冲突标注，数字 ↔ 来源双向映射；**无来源 = 一票否决**。
- 结论级依据链：每条主结论挂依据（自主模式强制）。
- 素材时效标注：标榜「当前流行」的内容须带出处 + 日期 + 近期证明，否则标「素材可能过时」或联网核最新。

### 7.6 元规则

- M2：验收含「用户满意」B 层判据（不只 A 层客观项）。
- M3：开工前偏好确认（先确认再干活）。
- M4：复述确认上限（复述 ≠ 无限确认，超限转自主）。

## 8. 降级预案与申报（实测补充）

1. **主控调度降级**：主控子代理连续 2 轮无法委派新任务 / 消息收到不响应 / 强制中断无效时，主代理可降级为直派执行子代理（执行层不变，主代理仍不直接写交付物）；**降级动作必须写入交付报告的"流程偏差申报"，不得静默绕过三层模型**。实测：降级后执行子代理仍可高质量交付，降级路径可行。
2. **行为变更申报表 = 重构类任务标准验收物**：重构前后输出的每一处差异逐条列出（位置 + 变更 + 原因：bug 修复 or 重构差异），作为差分核验的对照基准；禁止存在未申报的差异。
3. **迭代改进**：工作流本身也要被测试（实测发现的问题入问题清单，带实证编号），禁止赌"这次应该没问题"。
