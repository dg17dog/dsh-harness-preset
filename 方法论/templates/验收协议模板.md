# 验收协议模板（客观化门禁）

> 目的：防止"运动员兼裁判"——AI 写代码又自己判"完成了"。
> 办法：把"什么算完成"变成**可见、冻结、可复现**的检查条款和脚本，由机器执行、由用户抽查。
> 依据：驾驭工程工作法（本包 `工作法.md` §4 证据验收）。

## 适用边界

- **适用**：所有涉及改文件、跑命令、开发、修复的操作类任务
- **不适用**：纯聊天、问答、讨论（不产生操作）

## 流程（每次任务走这条流水线）

```
1. 接任务
2. 起草《验收条款》中文清单 + 检查脚本（草案）
   —— 条款必须：量化、可对照、有客观判定方法；禁止"应该没问题"这类措辞
3. 用户审查（抽查即可）：
   · 重点看条款有没有明显太松、有没有量化、判定方法是否客观
   · 你觉得松，当场改；觉得没问题，说"冻结"（或直接说"开始吧" = 默认冻结）
   · 明确说"免审"时，按模板默认从严执行
4. 冻结：批准后不得再修改条款和脚本（除非用户要求）
5. 实现
6. 跑验收脚本 → 输出 [PASS]/[FAIL] 报告，全部 [PASS] 才算完成
7. 附自证清单（做了什么、证据在哪个文件/哪行/哪个输出），用户抽查关键项
8. 用户拍板"完成"或要求返工
```

## 条款书写铁律（起草时必须遵守）

1. **量化**：能用数字不用形容词（"血条不重叠" → "关键遮挡数为 0"）
2. **客观判定**：每条都有机器可检查的方法（文件内容 / 端口状态 / 命令输出 / 截图）
3. **证据优先**：真实产物（文件、输出、截图） > 口头说明
4. **短小**：检查脚本每条一行能看懂；不细审也能抽查

## 完成定义

完成 = 验收脚本全绿 + 自证清单 + 用户抽查通过。三者缺一不算完成。

## 职责

- **执行方**：起草条款、实现、跑验收、提供证据；冻结后不擅自改标准
- **用户**：抽查条款、看报告、抽查关键证据、最终拍板
- **机器**：执行脚本，红灯就是红灯，不商量
