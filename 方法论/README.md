# 驾驭工程·通用规范包（L1 中立规范包）

> 软件无关的驾驭工程方法论封装包。**本包不绑定任何 AI 编程软件**：
> 方法论核心是文本，任何认文本规则的软件都能承载；到目标软件时按下方「翻译对照表」做最小适配即可。

## 包结构

| 文件 | 是什么 |
|---|---|
| `工作法.md` | 方法论核心：判型 / 三层子代理模型 / 子代理硬三条 / 证据验收 / 提问治理 / 探索模式 / 三环设计 / 降级申报 |
| `templates/规格文档模板.md` | 工程模式开工契约（目标+范围+约束+验收标准+交付物） |
| `templates/验收协议模板.md` | 客观化验收门禁（流程 / 铁律 / 完成定义） |
| `templates/探索契约模板.md` | 探索模式开工契约（方向 / 终止条件 / 负发现） |
| `README.md` | 本文件：挂载指南 |

## 三层封装

- **L1 中立规范包** = 本包。软件无关，现在就可用，不浪费。
- **L2 适配层** = 定了目标软件后，按下方对照表做最小翻译（半天量）：只改挂载方式，不改方法论内容。
- **L3 工具层** = 用目标软件自带能力模拟 dsh 专属工具（看板 → 待办列表；子代理 → 并行任务/子代理；记忆 → 记忆文件）。能模拟就模拟，模拟不了不强求——方法论层保住，价值就在八成以上。

## 决策树：要不要做插件

```
目标软件认文本规则文件？ ──是──→ 文档包（L1+L2），不做插件
        │否
        ├─ 有插件生态且只认插件？ ──是──→ 插件壳（壳内装 L1 文档，不重写方法论）
        └─ 是 dsh/同源体系？ ─────────→ 直接搬 preset，连翻译都省了
```

插件是**最后手段**：绑定具体软件私有 API，换软件作废；文档包处处可用。

## 翻译对照表（L2 适配）

| 目标软件类别 | 挂载方式 | 要点 |
|---|---|---|
| 命令行 AI 编程工具（Claude Code / Codex 系） | 规则文件（CLAUDE.md / AGENTS.md）+ 命令机制 | 工作法.md → 规则文件主体；三模板 → 斜杠命令/自定义指令 |
| IDE 系（Cursor / Windsurf / VS Code Agent 等） | rules 文件 / AGENTS.md 入口 | 确认规则加载目录与优先级；模板可放项目 templates/ |
| dsh 同源体系 | preset / 插件目录整体搬迁 | 直接搬，不用翻译（L1 在此场景退化为参考文档） |
| 只认自家插件 API 的封闭软件 | 插件壳 | 壳内注入 L1 文档路径，方法论不重写 |

## 使用流程

1. 新项目复制本包 → 2. 把 `工作法.md` 挂载为项目规则文件 → 3. 开工前判型（工程 / 探索）→ 4. 工程模式走《规格文档模板》，探索模式走《探索契约模板》→ 5. 派主控子代理（建目标 + 任务列表 + 分工表）→ 6. 派孙代理执行（提示词含硬三条）→ 7. 完工按《验收协议模板》跑检查脚本 → 8. 附自证清单，用户拍板。
