## 10. 过程处置与证据验收

### 10.1 孙代理任务提示词硬三条（缺一不可）

1. **空结果 = 合法终态**：检索 / 搜索无结果时禁止自动重试、禁止扩大范围重搜、禁止假装在跑；确需重试最多 2 次到顶即停。
2. **只做分派的那一件事**：产出明确的结果 / 证据 / 交付物，不得自由扩展任务边界（探索模式按 §11 替换）。
3. **卡住立即上报**：报告「卡点 + 已尝试动作」，禁止静默空转。

### 10.2 主代理验收三查与三件套

- 逐条核对：是否空转、是否超范围、是否把空结果当成功。
- 汇总三件套：完成了什么 / 证据在哪 / 没找到什么。
- **偏差与故障栏（必填，2026-09-23）**：交付报告须含固定栏「本轮故障 / 偏差 / 未决事项」——**即使为空也要写「无」**；缺栏 = 不合格。口径依据：B2-8（「鲁棒性错误不得自行消化」原只有自我约束）。
- **主代理零重查（裁决 C7）**：主代理不重查孙代理原文，只做格式门禁（产物齐全、可打开、物证清单在）+ 机检结论；要细节让主控子代理回溯。**例外见 §10.8 与 §10.9：子代理做不到的验收（真机/浏览器/宿主侧）与兜底动作（定位缺陷/补跑机检/跨环境调度），主代理必须亲自做或上报，不得以「零重查」为由跳过。**
- **内容验收**：主控子代理逐卡逐字段对照本卡验收标准核对并记录（content-review-vX.md，落 execution-work）；打回循环直至通过并计次留痕。
- **高风险独立审计（替代主代理重审）**，命中任一即派一次性独立审计代理（发包用 §7.1 甲段）：
  ① 不可逆操作（删除 / 覆盖不可恢复数据、对外发布、改基础设施配置）；
  ② 改动命中 §10.3 D1 实质判据；
  ③ 三件套缺失 / 自相矛盾。
  - **触发条件（2026-09-24 用户拍板）**：上述三条任一命中 → **必做**；未命中的 run → **每 run 至少一次抽检**（抽条款 / 产物任一项，报告落盘留痕）。判定与执行由你（主代理）负责，禁止用「预设没开/配置为关」结案（§10.9.1）。
  - **发包四件（强制）**：用户原始需求原文 + 冻结条款全文 + 产物路径清单 + 原始材料路径（缺件即发包不合格，效力同「缺段的任务卡不得发出」）——只给单文件路径的旧做法发现不了「条款漏了需求」。
  - **审计无法验证项的升级（2026-09-24 立规）**：审计代理对超出其能力面的验收项（真机 / 浏览器打开产物 / 起真实服务 / 宿主工具链）按 §7.1 标 `⚠ 无法验证`；该 ⚠ 项**强制升级为主代理亲自审查**——你按 §10.8 用宿主侧手段实测，或按 §10.8 显式申报验法降级（静默降级 = 不合格）；你也无法验证 → 逐级上报用户，**禁止第三种处理（静默结案）**。带 ⚠ 项的交付自动升级高风险，按 §10.8「存在未验证的核心承诺 ⇒ 必为阻塞项」处理。
- **攻击 / 审计建议必须逐条裁定并落盘（禁止直接转发）**（2026-09-23 强化；实测 0 次执行）：收到攻击报告后，**你（主代理）必须逐条裁定**——每条裁定为 `采纳 / 驳回 / 提请用户裁决` 三类之一并各附理由，产出 `adoption-log-vX.md` 落过程目录（§15 物证命名 schema）。
  - **禁止把攻击报告原样转发给执行侧**（§6 目录级隔离）；执行侧只能看到**你裁定后写入冻结条款的最终口径**。
  - **落盘判据**：攻击报告存在 ⇒ 必须有对应的采纳说明文件，二者条数逐条对应；缺件 = 流程不合格。
  - **攻击报告不存在**（未派攻击代理）⇒ 无采纳说明要求，但须在交付说明里写明「本轮未派攻击代理及原因」。
- 完成定义 = 验收脚本全 PASS + 三件套汇报 + 自证清单 + 用户抽查，三者缺一不算完成。

### 10.3 高风险判定口径（D1）

- 高风险②「改动 ≥3 文件或跨模块」中的「改动」，以三项**实质判据**为准：
  ① **覆盖 / 修改既有文件**；② **对外发布**；③ **跨模块代码改动**。
- **纯新建交付物**（在新建目录下创建新文件，不覆盖任何既有文件）**不计入**「改动」。
- 理由：该条立法意图是**爆炸半径**（不可逆性与影响面），文件数量本身不是风险源。
- 验收：凡声明「命中高风险②」的任务卡或交付报告，必须同时给出①②③三项实质判据的结论；**仅凭文件数量声明命中 = 不合格**，格式门禁即退回。

### 10.4 条款可判定性自检（D3）

凡写入规格文档 / 任务卡的可机检条款，发出前须过四项自检：
1. **量化口径自足**：字数 / 计数 / 行数类必须写明计什么、不计什么（如「仅计 CJK，去标题 / 表格 / 引用行」）；
2. **引用件随附**：条款引用的模板 / 附录必须随附本体，或明文声明「某几列即全部要求」；
3. **章节归属明确**：附录 / 术语表是否计入章数须写明；
4. **量词已定义**：「至少 / 恰 / 一句 / 若干处」等不得作为判定标准，须替换为可数口径。

**未过自检的条款不得发出**（效力等同「缺段的任务卡不得发出」）；执行中发现未覆盖的歧义，按 §5 上报四项格式上报。

### 10.5 验收判定口径与脚本同源（D2）

- 一切验收 / 评分脚本的**判定口径**（计字方法、章节归属、列数、覆盖率算法等）必须在**条款冻结时一并冻结**，与条款正文同源。
- 此后任何口径变更（含事后补充的放行口径）**必须同步更新对应脚本并重跑**，不得只改口径不改脚本；重跑输出须写**新物证文件**，不得覆盖旧物证。
- 脚本内每条断言必须可追溯到条款条目编号。
- **工具面统一口径**：物证行数核对一律用 `(Get-Content -Encoding UTF8).Count`；**禁止混用 `Measure-Object -Line`**（同一文件实测真值与 `-Line` 结果不一致，会污染物证清点）。

### 10.6 语义 ground truth 验收

- 自写单测通过 ≠ 行为语义正确（覆盖率再高也会出现「错误语义被测试断言固化」的假修复）。
- 涉及数值 / 统计 / 单位换算 / 转换类逻辑的任务，验收标准必须包含**独立于被测实现的语义基准**（测试方或第三方预置的手工算例 / 期望值），以 ground truth 对照判定，禁止仅凭自写单测判定行为正确。

### 10.7 断线 / 恢复防坑

- 关键验收必须落成文件物证（报告写入文件，不只在对话里）——对话会丢、总结会糊弄，文件不会。
- 恢复后第一问固定：「上次真的执行并验收了吗？给实际产物路径和验收数据，别用总结糊弄。」
- 主代理被「等子代理通知」卡住不算完成——等待期间必须产出独立成果或显式自查；把「等通知」当终点是编排层空转。
- 恢复依据 = 过程目录 + 执行输入 + 工作区全部文件；文件缺失即暂停并报用户，禁止凭记忆补造物证。

### 10.8 宿主侧验收归属与「验收手段降级」（2026-09-23 星露谷地交付失效后立规）

**背景**：一次游戏交付真机打开即白板，而四张卡 + 主控 + 主代理三层验收全绿（静态机检 60/60、exit 0）——因为**验收手段被静默降级**（真机→源码 grep），而降级从未走口径变更流程。

- **宿主侧验收归主代理**：凡验收需要**子代理沙箱做不到的能力**（在浏览器/真机里打开产物、起真实服务、驱动真实交互、宿主进程侧工具链），**由主代理亲自执行**——这不是「重查原文」，而是唯一能做的验收手段。子代理在任务卡里如实申报「本卡无法真机验证」是正确的，但**主代理不得据此判通过**。
- **验收手段弱化 = 口径变更（同权）**：任何把验法从强换到弱的行为——真机→静态、截图→grep、实测→推演、行为断言→文本存在性——**视同 §10.5 口径变更**，必须：① 在条款里显式写明新验法与其覆盖边界；② 同步更新脚本；③ 重跑并写新物证；④ 在交付报告里**申报「未采用已知替代方案」及其理由**。**静默降级 = 不合格**（本条与 §15 条款变更同权；全自动模式下由你自行执行并留痕）。
- **结论栏三值强制**：孙代理自检、主控核签、主代理门禁的结论栏一律三值——`✅验证通过 / ⚠未验证 / ❌不通过`。**未验证项必须进 ⚠，不得出现在 ✅ 里**；且凡有 ⚠，**自动升级为高风险**（触发 §10.2 独立审计）。
- **阻塞项判定规则**：**存在未验证的核心承诺 ⇒ 必为阻塞项**。核心承诺 = 用户据此决定是否收货的那句话（如「双击即玩」「数据准确」）。交付文本写「无阻塞项」前必须逐条核对此规则。
- **已知替代通道必须用**：若历史结论/记忆里已有可行的替代验收通道（如宿主侧 Playwright），**必须采用或显式申报未采用的理由**；「沙箱内做不到」不等于「无法验证」。

### 10.9.0 过程硬约束（纯提示词工程版，2026-10-01 起）

> **形态变更声明**：本节前身是「工具级硬门禁」（插件在派发瞬间拒绝调用）。2026-10-01 用户拍板取消工具级门禁（约束分档实验结论），全流程改为**纯提示词工程**——下列约束没有任何工具会替你拦截，**执行者是你自己**，事后由合规审计脚本（若安装）对照会话日志记账。违规不再有「当场报错」，只有「事后追责」——请按自律标准执行。
